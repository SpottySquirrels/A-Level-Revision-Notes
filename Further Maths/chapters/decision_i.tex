    \section{Bubble Sort}
        \subsection{Description}
            Bubble sort is an algorithm that sorts an unsorted list of data.
            It passes through the list, checking each pair of items to see if they need to be swapped to be in order.
            For example, if it were sorting a list of numbers into numerical order and it found the pair 2, 1, it would swap them.
            This is an example of a single bubble sort pass, with each comparison marked:
            \begin{verbatim}
                [3   5]  8   2   5   6   3
                 3  [5   8]  2   5   6   3
                 3   5  [8   2]  5   6   3
                 3   5   2  [8   5]  6   3
                 3   5   2   5  [8   6]  3
                 3   5   2   5   6  [8   3]
                 3   5   2   5   6   3   8
            \end{verbatim}
            Now, the 8 is in the right place, and the bubble sort will do another pass, ignoring the 8, since it must be in the right place after 1 pass, since it is the largest number.
            In general, after $n$ passes, the last $n$ items are sorted.
            Bubble sort gets its name from this property of the largets elements `bubbling' to the top (end) of the list.
            If the algorithm does a pass without swapping any items, it must have already finished sorting the list, so it will return early.

            Example of bubble sort:
            \begin{center}
            \begin{tabular}{c c c c c c c c}
                Pass 1: &3 &5 &8 &2 &5 &6 &3 \\
                Pass 2: &3 &5 &2 &5 &6 &3 &\textbf{8} \\
                Pass 3: &3 &2 &5 &5 &3 &\textbf{6} &\textbf{8} \\
                Pass 4: &2 &3 &5 &3 &\textbf{5} &\textbf{6} &\textbf{8} \\
                Pass 6: &2 &3 &3 &\textbf{5} &\textbf{5} &\textbf{6} &\textbf{8} \\
                Pass 7: &2 &3 &\textbf{3} &\textbf{5} &\textbf{5} &\textbf{6} &\textbf{8} \\
                \multicolumn{8}{c}{\textbf{No more swaps; sort complete.}}
            \end{tabular}
            \end{center}
            Notice that pass 6 is the same as pass 7, as only on pass 7 has the algorithm not performed any swaps.

        \subsection{Order}
            \begin{theorem}
                Bubble sort has an order of $\bigO(n)$
            \end{theorem}
            \begin{proof}
                Let $n$ be the number of elements in the list to be sorted.
                This means that (in the worst-case scenario) the bubble sort will have to do $i-1$ pass to guarantee that every item has been sorted (since after the $i$th pass, $i$ items have been sorted, $n-i$ items will be left to sort, the $i$th item must also be sorted).
                In the $i$th pass, $i-1$ items will have been sorted, so the total number of comparisons will be:
                $$\sum_{i=1}^n(n-i)=\frac{n(n-1)}{2}=\frac{1}{2}n^2+\frac{1}{2}n$$
                Taking the fastest-growing term of $\frac{1}{2}n^2+\frac{1}{2}n$ (the $\frac{1}{2}n^2$ term) and discarding the constant coefficient ($\frac{1}{2}$), this gives $n^2$, thus the order of the bubble sort algorithm is $\bigO(n^2)$.
            \end{proof}
        
        \subsection{Implementation}
            In pseudocode, this is an example implementation of a bubble sort algorithm:
            \begin{verbatim}
// Sorts a list using bubble sort; returns sorted list
// Example:
//     Input:  [3, 2, 7, 3, 5]
//     Output: [2, 3, 3, 5, 7]
//     Explanation: The unsorted input is sorted so the the numbers are returned in order
FUNC bubble_sort(list):            // Takes an unsorted list as input
    VAR n = list.UPPER_BOUND

    FOR (i = 0 TO n):                     // Goes through each pass
        VAR hasSwapped = FALSE
        FOR (j = 0 TO n - i):             // Goes through each value in the list
            IF (list[i] > list[j + 1]):   // Checks if items need swapping
                hasSwapped = TRUE
                VAR temp = list[j + 1]    // Swaps items
                list[j + 1] = list[i]
                list[i] = temp
            END IF
        END FOR

        IF (NOT hasSwapped):   // If it doesn't find any items to swap, the list must be sorted
            OUTPUT("No more swaps; sort complete.")
            RETURN list        // Return the sorted list early, since there are no more swaps
        END IF
    END FOR

    RETURN list                // Returns sorted list
END FUNC
            \end{verbatim}

    \section{Quick Sort}
        \subsection{Description}
            A quick sort is a recursive sorting algorithm.
            It begins by choosing a `pivot' in the middle of the list (the $\lceil\frac{n}{2}\rceil$th element).
            Then, it splits the list into two smaller sub-lists, the left and the right.
            The left sub-list will contain all elements less than or equal to the pivot, and the right list will contain all elements greater than the pivot.
            The pivot is then left in the middle and is now sorted.
            Then, each sub-list with a length greater than 1 is sorted using quick sort, hence quicksort is recursive.

            This is an example of quick sort (the pivot will be in brackets, and then sorted elements will be bold):
            \begin{center}
            \begin{tabular}{c c c c c c c c c c c}
                &&Pass 1: &3 &5 &8 &(2)  &5 &6 &3 \\
                &&Pass 2: &\textbf{2} &3 &5 &8  &(5) &6 &3 \\
                &&Pass 3: &\textbf{2} &3 &(3) &5 &\textbf{5} &8 &(6) \\
                &&Pass 4: &\textbf{2} &3 &(3) &5 &\textbf{5} &\textbf{6} &8 \\
                \multicolumn{11}{c}{\textbf{All sub-lists contain only 1 item; sort complete.}}
            \end{tabular}
            \end{center}

        \begin{theorem}
            Quick sort has an order of $\bigO(n^2)$.
        \end{theorem}
        \begin{proof}
            The worst case scenario for quicksort is where the pivot consistently falls on the maximum/minimum pivot, leaving the sub-lists with lengths 0 and $n-1$.

    \section{Order of Algorithms}
        The order of an algorithm is how long it takes an algorithm to finish, based on the size of its input $n$, in the worst-case scenario.
        This is also called its time complexity, and is written as $\bigO(f(n))$, where $f(n)$ is a function of the algorithm's input size.

        For example, the linear search algorithm looks through each element in a list one by one, checking to try to find a specific item.
        The worst case for linear search is if the item being looked for is either not in the list, or is the final item in the list, meaning that the algorithm has to check all $n$ elements.
        This means that linear search has an order of $\bigO(n)$.

        The order of an algorithm can be used to find the time taken for an algorithm to finish based on other recorded times. For example, if an $\bigO(n)$ algorithm takes 5ms to finish with 100 items, it will take 10ms to finish with 200 items.
        
        Common orders are $\bigO(1)$ (constant time), $\bigO(n)$ (linear time), $\bigO(n^2)$ (quadratic time), and $\bigO(n^3)$ (cubic time).
        Quadratic, cubic, etc. time is also called polynomial time.
        An algorithm is considered more efficient if its order scales slower with a bigger input.
        For example, if an algorithm runs in constant time ($\bigO(1)$), then that is considered very good, since with an arbitrarily big input, it will still run in the same amount of time.
        On the other hand, an algorithm with an order of $\bigO(2^x)$ (exponential time) would be considered inefficient and slow, since it scales very quickly as the input grows, making it very slow for large inputs.
